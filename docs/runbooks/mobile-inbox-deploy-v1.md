# M7 deploy runbook: the mobile inbox Worker (v1)

Owner steps only. Nothing here was run by the agent that built M7 (completion-kickoff-v1.md
section 0's stop rule: cloud accounts, deployment and real tokens are never the agent's step).
Everything up to this point (the hub code, the Worker source, the D1 migration, the wrangler
config) is already built and tested against the fake and local-directory transports; this is
only the "turn it on for real" steps.

## 1. Prerequisites

- A Cloudflare account (free tier is enough; see Spec v10 section 17.4 for the cost reasoning).
- `npm install -g wrangler` or use `npx wrangler` from the steps below.
- Node 22, already required by ctxd itself.

## 2. Deploy the Worker

```bash
cd cloud/mobile-inbox-worker
npm install
npx wrangler login

npx wrangler d1 create ctxd-mobile-inbox
# copy the printed database_id into wrangler.toml's [[d1_databases]] block

npx wrangler d1 migrations apply ctxd-mobile-inbox --remote
npx wrangler deploy
# note the printed *.workers.dev URL; you'll need it in steps 4 and 5
```

## 3. Mint tokens

Tokens are never generated by ctxd itself; they are random values you create and insert as their
SHA-256 hex hash (the raw value is only ever shown once, here, and then goes straight into the
Keychain or the phone app's own settings, never into a file ctxd can read back).

```bash
# one 'hub' token for this Mac (pull + ack + status + brief publish)
HUB_TOKEN=$(openssl rand -hex 32)
HUB_HASH=$(printf '%s' "$HUB_TOKEN" | shasum -a 256 | cut -d' ' -f1)
npx wrangler d1 execute ctxd-mobile-inbox --remote --command \
  "INSERT INTO tokens (token_hash, role, label, created_at) VALUES ('$HUB_HASH', 'hub', 'hub', datetime('now'))"
echo "Hub token (save this, it is shown once): $HUB_TOKEN"

# one 'client' token per phone app, e.g. for "claude-mobile"
CLIENT_TOKEN=$(openssl rand -hex 32)
CLIENT_HASH=$(printf '%s' "$CLIENT_TOKEN" | shasum -a 256 | cut -d' ' -f1)
npx wrangler d1 execute ctxd-mobile-inbox --remote --command \
  "INSERT INTO tokens (token_hash, role, label, created_at) VALUES ('$CLIENT_HASH', 'client', 'claude-mobile', datetime('now'))"
echo "Client token for claude-mobile (save this): $CLIENT_TOKEN"
```

Repeat the client-token block once per phone app or Shortcut you want to give capture access to.

## 4. Point the Mac at the Worker

```bash
ctxd inbox set-token "$HUB_TOKEN"   # stores it in the macOS Keychain, never in config.toml
```

In `config.toml`, set:

```toml
[inbox]
transport = "cloudflare"
endpoint = "https://ctxd-mobile-inbox.<your-subdomain>.workers.dev"
```

## 5. Connect the phone apps

- **ChatGPT Actions:** import `cloud/mobile-inbox-worker/openapi.yaml`, replacing its placeholder
  `servers.url` with your Worker's real URL, and set the Action's bearer token to a client token
  from step 3.
- **iOS Shortcuts:** build a "Get Contents of URL" shortcut, method `POST`, URL
  `https://<your-worker>.workers.dev/v1/inbox/entries`, header `Authorization: Bearer
  <client-token>`, JSON body `{"scope": "...", "kind": "note", "title": "...", "body": "...",
  "capturedAt": "..."}` (the title can be a Shortcuts text action; capturedAt can be `Current
  Date` formatted as ISO 8601).
- **claude.ai mobile:** until it supports custom Actions directly, route through the ChatGPT
  Actions path above or a Shortcut, the same way any other phone HTTP client would.

## 6. Turn the flag on

```toml
[features]
mobile_inbox = true
```

or `CTXD_FEATURE_MOBILE_INBOX=true` in the environment. Run `ctxd inbox pull` by hand once to
confirm a capture round-trips, then check `ctxd review` for the new `proposed` entry attributed
to `mobile-inbox`.

## 7. Schedule it (optional, but needed for unattended use)

`ctxd inbox pull` is a manual, on-demand command, the same way `ctxd sync` is: this milestone did
not add it to `ctxd server`'s own scheduled loop. For hands-off capture, schedule it the same way
W4 scheduled `ctxd backup`: a `launchd` agent with `StartCalendarInterval` (or a cron entry)
running `ctxd inbox pull` every few minutes. A dedicated `ctxd inbox pull schedule` installer,
mirroring `src/cli/backup-schedule.ts`, is a reasonable next slice if this becomes the common
case; it was not built here because it was not in M7's own slice list.

## 8. Optional: allowlisted brief publishing

Only if you want the phone to see minimal project context back:

```toml
[inbox]
publish_scopes = ["sample-app"]

[features]
"mobile_inbox.publish_briefs" = true
```

`ctxd inbox pull` then also publishes a `micro` brief for each listed scope after every pull.
Sealed, `local-only` and `home`-replication scopes are never published, however they are listed
here (Spec v10 section 17.5).

## 9. Revoking access

To cut off a lost or compromised phone: delete its row from the `tokens` table
(`npx wrangler d1 execute ctxd-mobile-inbox --remote --command "DELETE FROM tokens WHERE
token_hash = '<hash>'"`). To stop the hub entirely: turn `mobile_inbox` back off in `config.toml`,
or delete the hub's own token row the same way.
